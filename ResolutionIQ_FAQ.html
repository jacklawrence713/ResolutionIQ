1 Engine Basics 6 Questions
Q What does ResolutionIQ actually evaluate?
A
ResolutionIQ takes a delinquent loan's financial profile, hardship details, and property information and evaluates it against the complete eligibility rules for all five major investors — FHA, Fannie Mae (FNMA), Freddie Mac (FHLMC), VA, and USDA. It produces a ranked waterfall of all eligible loss mitigation options, along with an audit trail showing exactly why each option was approved or denied, with citations to the governing regulatory section.
Q Does it replace my loss mitigation team?
A
No. ResolutionIQ is a decision support tool, not a decision-making system. Your loss mitigation specialists retain final determination authority. The engine eliminates the manual guideline-lookup and calculation work, so specialists can focus on borrower interaction, documentation, and judgment calls. Think of it as a highly accurate second opinion that happens in under 30 seconds.
Q Which investors does it cover?
A
All five major agency investors: FHA (HUD), Fannie Mae (FNMA), Freddie Mac (FHLMC), the Department of Veterans Affairs (VA), and USDA Rural Development. Private label, non-agency, and HELOC products are on the roadmap for 2027.
Q How current are the rules?
A
The engine is current through March 2026. This includes FHLMC Bulletin 2026-2 (effective February 11, 2026 — the Disaster Flex Mod dual DLQ gate and forbearance increment reduction), FHA ML 2024-02 (Payment Supplement), and VA Circulars 26-24-2, 26-24-3, and 26-25-2 (VASP wind-down). Material guideline changes are incorporated within 30 days for Enterprise subscribers.
Q How accurate is it?
A
  • 97–99% accuracy on standard delinquency scenarios.
  • 93–97% on disaster and imminent default cases (which involve more servicer judgment).
  • 90–95% when input fields are incomplete.
The engine has 449 automated test cases with a 100% pass rate. The primary source of real-world divergence is servicer discretion on judgment-call fields (e.g., "can the borrower afford the modified payment") — those fields require human input.
Q What does the audit trail look like?
A
Each eligible or ineligible option includes a list of audit nodes — individual pass/fail checks. Each node states what was tested, what value was found, whether it passed or failed, and the regulatory citation. For example: "≥ 90 days DLQ at evaluation date — PASS — 4 months — §9206.1(c)(v), Bulletin 2026-2, eff. Feb 11, 2026". This is the documentation you need for investor repurchase challenges and regulatory examinations.
2 Input Fields & Data 5 Questions
Q What happens if I don't fill in all the fields?
A
Missing fields default to their baseline values (usually false/zero). If a critical field is missing — like DLQ months, UPB, or hardship type — most options will be denied because the engine can't confirm eligibility. Always populate the core financial fields, DLQ, hardship type/duration, and borrower intent for a meaningful evaluation. See the Field Reference Guide for required vs. optional fields.
Q I don't know the borrower's FICO score. What should I enter?
A
FICO is only used for the FNMA and FHLMC Imminent Default Rule 2 determination. If you don't have it, leave the field blank — the engine will not trigger the FICO-based ID criterion, but other ID Rule 2 criteria (housing ratio, prior 30-day DLQs) can still satisfy the requirement. The engine will note that the FICO criterion could not be evaluated.
Q The loan has disaster hardship but I haven't confirmed FEMA designation yet. Can I still run the evaluation?
A
Yes — run it with the disaster hardship flag set but FEMA designation unchecked. The engine will show the disaster options as ineligible due to missing FEMA designation, which is accurate. Once FEMA designation is confirmed, re-run with that flag set to see the full disaster pathway.
Q How does the engine handle ARM loans?
A
ARM-specific fields (current index, margin) are available for FNMA and FHLMC. The engine uses them for modification rate calculations when applicable. If left blank for a fixed-rate loan, they have no effect on eligibility.
Q Can I run the same loan through multiple investors?
A
Yes. The engine evaluates the selected investor's rules based on the loanType field. To compare across investors (e.g., if you're not sure of investor identity), run the evaluation once per investor by changing loanType. The Professional and Enterprise tiers include a side-by-side comparison mode.
3 Specific Option Questions 8 Questions
Q Why is FHA Payment Deferral showing as ineligible even though the borrower is 4 months DLQ?
A
The most common causes are:
  • (1) Hardship is not marked as "Resolved" — FHA Payment Deferral requires the hardship to be resolved.
  • (2) Disaster hardship flag is set — disaster hardship routes to disaster options and blocks standard deferral.
  • (3) Prior deferral spacing — if a deferral was used within the past 12 months, another is blocked.
  • (4) Cumulative cap — if 12 or more months have been previously deferred, no further deferrals are available.
Q Why does the engine show FHA 40-Year Combination Mod but not 30-Year Mod?
A
The FHA 40-Year Combo requires that (1) 360-month re-amortization does NOT achieve the target payment (canAchieveTargetByReamort = false) AND (2) 480-month re-amortization DOES achieve the target (canAchieveTargetBy480Reamort = true). If the 30-Year Mod is ineligible, it means the 360-month test is passing — the engine believes re-amortization alone achieves target. Verify your targetPayment and canAchieveTargetByReamort inputs.
Q The FNMA Streamlined Flex Mod is showing ineligible. The borrower is 4 months DLQ.
A
FNMA Streamlined Flex Mod requires DLQ of at least 3 months (90+ days), which 4 months satisfies. Check whether: (1) fnmaDisasterHardship is set to true — disaster hardship blocks the streamlined path; (2) a prior failed TPP (fnmaFailedTPP12Months) is blocking; (3) the loan age is under 12 months. For Streamlined, no solicitation letter is required on FNMA (unlike FHLMC which requires §9206.7 solicitation).
Q Why does FHLMC Disaster Flex Mod require TWO DLQ conditions?
A
This is a change from FHLMC Bulletin 2026-2, effective February 11, 2026. Under §9206.1(c)(v) as amended, the loan must be: (1) current or < 60 DLQ at the time of the disaster event, AND (2) ≥ 90 DLQ at the evaluation date. Before Bulletin 2026-2, only the at-disaster condition applied. Both fhlmcDLQAtDisaster (set to 0 or 1 for the at-disaster test) and delinquencyDays (90+ for the evaluation date test) must be populated correctly.
Q The VA Disaster Extend Modification shows eligible, but what exactly does it do?
A
It extends the original maturity date of the note by up to 12 months beyond the original maturity. It does NOT re-amortize the loan, does NOT change the interest rate, and does NOT change the monthly payment amount. It is purely a maturity date extension — the borrower "catches up" by having more time at the back end of the loan. VA Regional Loan Center approval is required if the extension exceeds 12 months. Authority: VA M26-4 Ch. 5.06; Circular 26-24-3 §3.a.
Q Can the FHA Payment Supplement be used alongside a modification?
A
No. Payment Supplement is the last-resort option in the FHA waterfall — it is only eligible when standard modifications (30-Year Mod, 40-Year Combo) are ineligible. The engine enforces this through waterfall sequencing: canAchieve360 and canAchieve480 must both be false for Payment Supplement to appear as eligible. It also requires that the 30% partial claim statutory cap has not been exhausted (PS uses a Partial Claim per ML 2024-02).
Q What is the USDA MRA and how is its cap calculated?
A
The MRA (Mortgage Recovery Advance) is a deferred subordinate lien used to capitalize arrearages in USDA Streamline Modifications. The cap is 30% of the UPB at the date of initial default (usdaUpbAtInitialDefault field). For example, if the UPB at initial default was $150,000, the maximum MRA is $45,000. After modification, the borrower must make 36 consecutive timely payments per §3555.304(d).
Q Why is VA Compromise Sale showing "VA RLC Approval Required"?
A
This is not an error — it is a required regulatory disclosure. Per VA M26-4 Ch. 5 §3.A and Circular 26-24-2, servicers have NO delegated authority to approve VA Compromise Sales. Every VA Compromise Sale, without exception, requires VA Regional Loan Center approval. The engine displays this as a mandatory audit node on every eligible Compromise Sale result so it is not overlooked in the workflow.
4 Disaster Loans 5 Questions
Q How do I know which disaster path to use — forbearance, modification, or extend mod?
A
The disaster sequence is generally:
  • (1) Disaster Forbearance first — immediate relief while hardship is ongoing.
  • (2) Disaster Modification after forbearance completes — re-amortizes the loan.
  • (3) Disaster Extend Modification if modification is not achievable — VA-specific, extends maturity only.
The engine routes automatically based on hardshipType, prior workout history, and workout state. For VA loans, the extend mod does NOT require a prior disaster modification — only a prior forbearance.
Q The FHLMC Disaster Flex Mod is failing the evaluation-date DLQ gate. The loan is 2 months DLQ.
A
Per Bulletin 2026-2 (eff. Feb 11, 2026), FHLMC Disaster Flex Mod requires ≥ 90 days DLQ at the evaluation date. 2 months (approximately 60 days) does not meet this threshold. The loan may still be eligible for the Standard Flex Mod if other criteria are met. If the disaster hardship flag blocks Standard Flex Mod, the servicer should continue disaster forbearance until the 90-day threshold is reached.
Q For FHA disaster loans, what's the difference between Disaster Standalone PC and the regular Standalone PC?
A
The Disaster Standalone Partial Claim is specifically for disaster-affected borrowers who were current at the time of the disaster. It does not require the borrower to demonstrate they cannot afford the pre-hardship payment (unlike the standard Standalone PC which requires fhaBorrowerCanResumePreHardship = true). The disaster version is also available to borrowers who are unresponsive, unless the servicer has flagged fhaOwlBorrowerUnresponsive.
Q We have a VA loan where the borrower was current at the disaster but now has not responded. Can we still use disaster options?
A
Generally no — VA disaster modification options require QRPC (Qualified Right Party Contact). Unlike some FHA disaster provisions, VA requires borrower engagement. If the borrower remains unresponsive, the servicer should document outreach attempts and may need to proceed to liquidation options with VA RLC involvement.
Q A USDA borrower had a prior disaster forbearance. What workout options are now available?
A
After USDA Disaster Forbearance completes, the primary next steps are:
  • USDA Disaster Modification — re-amortizes the loan; requires prior forbearance as prerequisite.
  • USDA Disaster Term Extension — if modification is not achievable.
Ensure usdaPrevWorkoutForbearance = true and usdaWorkoutStateActivePassed = true to unlock these options in the engine.
5 Imminent Default 4 Questions
Q What is imminent default and when does it apply?
A
Imminent default (ID) is a determination that a borrower who is current or minimally delinquent is at high risk of defaulting. It is relevant for FNMA Standard Flex Mod and FHLMC Standard Flex Mod — both require DLQ ≥ 2 months OR documented imminent default for a current/1-month DLQ borrower. ID determination requires meeting both Rule 1 AND Rule 2 criteria. It is NOT available for FNMA/FHLMC Streamlined or Disaster Flex Mod variants.
Q What's the difference between FNMA and FHLMC imminent default rules?
A
Criterion FNMA FHLMC
Rule 1 — Residence Primary residence Primary residence
Rule 1 — Hardship Long-term hardship Long-term hardship
Rule 1 — Reserves < 3 months PITIA < $25,000
Rule 2 — FICO ≤ 620 ≤ 660
Rule 2 — Housing Ratio > 55% > 40%
Rule 2 — Prior DLQs 2+ in 12 months 2+ in 6 months
Key differences: FHLMC uses a $25,000 dollar threshold for reserves vs. FNMA's 3-month PITIA ratio; FHLMC FICO threshold is 660 vs. FNMA's 620; FHLMC housing ratio threshold is 40% vs. FNMA's 55%; FHLMC uses a 6-month lookback vs. FNMA's 12-month.
Q Can a borrower with 0 months DLQ ever be eligible for Payment Deferral via imminent default?
A
For FNMA: Payment Deferral via ID path requires DLQ ≥ 2 months even if imminent default is documented. A truly current borrower (DLQ = 0) cannot access Payment Deferral even with ID. For FHLMC: same rule — Payment Deferral requires DLQ 2–6 months; ID does not lower this threshold. Flex Mod, however, CAN be accessed at DLQ = 0 with documented ID (FNMA and FHLMC).
Q The imminent default determination was made by our system but the engine still shows Flex Mod ineligible. Why?
A
Check the following:
  • fnmaImminentDefault (or fhlmcImminentDefault) must be set to true.
  • Both Rule 1 AND Rule 2 must be satisfied — the engine checks each criterion individually.
  • A common miss is Rule 1 requiring fnmaLongTermHardship = true AND fnmaCashReservesLt3Mo = true — both must pass.
  • Check each ID sub-field: long-term hardship flag, cash reserves flag, FICO, housing ratio, prior DLQ flag.
6 Compliance & Regulatory 4 Questions
Q Is the engine's output sufficient for investor repurchase defense?
A
ResolutionIQ provides a documented, regulatory-cited audit trail that demonstrates the servicer followed a systematic, rules-based evaluation process aligned with investor guidelines. This is strong evidence in a repurchase defense. However, the audit trail supplements — it does not replace — borrower communication records, income documentation, BRP files, and servicer notes. The combination of engine output + complete file documentation provides the strongest defense.
Q How does the engine handle Regulation X (CFPB 12 CFR §1024.41) requirements?
A
The current engine evaluates investor eligibility rules (what options the borrower qualifies for under investor guidelines). Regulation X procedural requirements — acknowledgment notices, 5-day acknowledgment, 30-day evaluation deadline, appeal rights — are on the roadmap as an integrated compliance checklist (Q4 2026). For now, Reg X procedural compliance remains the servicer's responsibility using existing procedures.
Q What if an investor updates their guidelines and the engine hasn't been updated yet?
A
The engine reflects rules as of its last update (March 2026 for the current version). Subscribers receive notification when material guideline changes are identified. Enterprise subscribers receive updates within 30 days of material changes; Professional within 60 days. For any guideline change you become aware of before the engine update, document the variance in your servicer notes and apply the new rule manually. The engine's regulatory citation on each audit node allows you to identify exactly which rule version was applied.
Q Does using ResolutionIQ create any liability for the technology provider?
A
ResolutionIQ is a decision support tool. The servicer retains full responsibility for all loss mitigation determinations. The engine's output is a recommendation, not a regulatory determination. See the Terms of Use for complete limitation of liability provisions. The servicer must independently verify all engine outputs against current investor guidelines before implementing any loss mitigation action.
7 Technical & Implementation 4 Questions
Q How long does an evaluation take?
A
Under 30 seconds in the standard web interface. Via API, typical response time is under 2 seconds per loan evaluation. Batch processing (Enterprise tier) can evaluate 50,000 loans overnight.
Q Can ResolutionIQ integrate with our LOS?
A
LOS integration is available for Enterprise subscribers. Native connectors for Encompass (ICE Mortgage Technology) and MSP (Black Knight) are on the roadmap for Q3 2026. In the interim, the Enterprise API allows any LOS with an API layer to push loan data and receive evaluation results programmatically. Custom integration builds are available as a paid add-on service.
Q What data does ResolutionIQ store?
A
In the current web application version, no loan data is stored server-side — all evaluation processing happens in the browser. API and Enterprise versions store evaluation logs (input hash, output, timestamp, user) for audit purposes. All data is encrypted at rest and in transit. See the Privacy Policy and Terms of Use for complete data handling details.
