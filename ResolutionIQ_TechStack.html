Platform Overview

ResolutionIQ is a single-page web application (SPA) that evaluates mortgage loans for loss mitigation eligibility across five investors (FHA, FNMA, FHLMC, VA, USDA). It operates as a pure client-side React application backed by Supabase for persistence, authentication, and real-time updates. There is no custom backend server — all business logic runs in the browser.

Local Development — Quick Start

💻
Prerequisites & Setup
Developer Onboarding
Node 18+

Prerequisites: Node.js 18 or higher, npm 9+, Git. No other global tooling required.

# 1. Clone the repository
git clone https://github.com/jacklawrence713/ResolutionIQ.git
cd ResolutionIQ

# 2. Install dependencies
npm install

# 3. Create environment file (copy from template or create manually)
#    Add your Supabase project credentials:
VITE_SUPABASE_URL=https://<your-project>.supabase.co
VITE_SUPABASE_ANON_KEY=<your-anon-key>

# 4. Start the dev server
npm run dev
# → http://localhost:5173

# 5. Run tests (pick any file)
node test_evaluations.mjs
node test_evaluations_id_severe.mjs

Build for production: npm run build → outputs static files to dist/. Deploy by pushing to master — GitHub Actions handles the rest.

Core Technology Stack

⚛️
React 18
UI Framework
v18.x
  • Functional components only — no class components
  • Hooks: useState, useEffect, useRef, useMemo, useCallback
  • All application state managed via useState at the root ResolutionIQApp component; props drilled to children
  • No Redux, Zustand, or other state management library
  • React.useRef used for imperative guards (e.g., overlaysLoaded ref pattern to prevent premature Supabase writes)
🔷
TypeScript
Type System
v5.x
  • Strict mode enabled (tsconfig.json)
  • Inline interface definitions for LoanData, EvalResult, EvalNode, Profile, Overlays
  • Type assertions used in Supabase response destructuring
  • All eligibility engine functions typed: (loan: LoanData, overlays: Overlays) => EvalResult[]
⚡
Vite
Build Tool & Dev Server
v5.x
  • Dev server: npm run dev → http://localhost:5173 with HMR
  • Production build: npm run build → outputs to dist/
  • Config: vite.config.ts — standard React + TS preset, no custom plugins
  • Environment variables: VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY loaded from .env
🎨
Tailwind CSS
Styling
v3.x
  • Utility-first CSS — all styling via Tailwind class names directly in JSX
  • No CSS modules, styled-components, or external UI component library
  • Custom color palette defined in tailwind.config.js (brand blues: #1e3a5f, #2d5fa6)
  • Print utilities (print:hidden, print:block) used for report rendering
  • Responsive breakpoints used minimally — app is desktop-first
🟢
Supabase
Backend-as-a-Service
Cloud · JS SDK v2
  • Authentication: Email + password via Supabase Auth; JWT tokens managed automatically by SDK; session persisted to localStorage
  • Database: PostgreSQL (managed by Supabase); 4 application tables (see Database Schema section)
  • Row-Level Security (RLS): All tables have RLS enabled; policies enforce per-user data isolation
  • Realtime: Supabase Realtime subscription on evaluations table drives live dashboard updates without polling
  • Client: @supabase/supabase-js v2 — single client instance initialized at module scope in App.tsx

Database Schema

TablePurposeKey Columns
profiles User accounts, roles, approval status id (FK → auth.users), email, full_name, role (admin/supervisor/specialist), approved (bool)
evaluations Saved loan cases and eligibility results id, user_id, loan_data (jsonb), results (jsonb), checked_docs (jsonb), assignee_email, sla_start_date, foreclosure_sale_date, status, created_at

servicer_overlays Organization-wide servicer overlay configuration id, org_id (text, unique, default: "default"), config (jsonb), updated_at, updated_by (FK → auth.users)

{
  minFICO: number | "",          // e.g. 580 — options requiring FICO below this are ineligible
  maxDLQMonths: number | "",     // e.g. 18 — options only valid below this DLQ threshold

Key Architectural Patterns

PatternDescription
Node audit system Every eligibility criterion is recorded as node(question, answer, pass). eligible = nodes.every(n => n.pass). Provides full audit trail per option per investor.
Monorepo-in-one-file All components, constants, types, and engine functions live in src/App.tsx. No module splitting. Optimizes for rapid iteration; complexity managed with named sections and // ──── SECTION ──── comments.
Overlays-loaded guard overlaysLoaded = React.useRef(false) prevents the overlay save useEffect from writing empty state to Supabase before the initial load from the database completes.
Realtime subscription Supabase Realtime channel on evaluations table pushes INSERT/UPDATE/DELETE events to the dashboard — no polling required.
Print-to-PDF report printReport() builds a full HTML string with all results and audit nodes, opens it in a new window, and calls window.print(). No PDF library dependency needed.

Known Architectural Limitations

LimitationDetailImpact
Single-tenant only org_id is hardcoded to "default" in overlay queries Cannot serve multiple organizations from one Supabase project without schema changes
Monolithic file All code in src/App.tsx (~6,300 lines) Increasing file size impacts IDE performance and merge conflict risk; consider splitting into modules past ~8,000 lines
Test engine duplication Eligibility engine is copied inline into each of the 6 test .mjs files — not imported from App.tsx Engine changes must be manually synced to all test files; risk of drift
No session timeout Supabase JWT refresh runs indefinitely; no inactivity logout implemented Compliance risk for PII access on shared workstations
No mobile support Desktop-first layout; no responsive breakpoints for small screens Unusable on phones/tablets by design

External Integrations

FRED (Federal Reserve Economic Data) Fetches current PMMS 30-year fixed mortgage rate for net present value calculations HTTP GET — public CSV endpoint (fredgraph.csv?id=MORTGAGE30US). No API key required. Rate is cached in localStorage with timestamp.
Supabase Auth User registration, login, session management REST + JWT via Supabase JS SDK. Email/password. Session stored in localStorage.
Supabase Database All persistent data storage REST (PostgREST) via Supabase JS SDK. All queries use the typed client.
Supabase Realtime Live dashboard updates WebSocket via Supabase Realtime channel. Subscribed to evaluations table changes.

Security Considerations

  • RLS: All Supabase tables have Row-Level Security enabled. Users can only read/write their own data; supervisors/admins have elevated access via role-check policies.
  • Anon key exposure: The Supabase anon key is embedded in the client bundle (standard Supabase pattern). RLS is the security boundary — the anon key alone cannot bypass RLS policies.
  • No server-side secrets: No private API keys or server-side code. All sensitive configuration lives in Supabase project settings.
  • Auth: JWT sessions expire per Supabase default (1 hour rolling); refresh tokens handled automatically by the SDK.
  • PII: Loan data (borrower name, SSN, address) may be stored in the evaluations.loan_data JSONB column. Ensure Supabase project is configured with encryption at rest (enabled by default on Pro plan).
