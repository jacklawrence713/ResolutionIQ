ResolutionIQ
Admin Setup Guide

Database provisioning, user management, servicer overlay configuration, and ongoing administration for ResolutionIQ system administrators.
Version 1.0 · March 2026 · Restricted — Admins Only

Prerequisites

  • Admin access to the ResolutionIQ application (admin role in Supabase profiles table)
  • Access to your organization's Supabase project dashboard (or credentials from ResolutionIQ if hosted)
  • For self-hosted: Node.js 18+, a GitHub account (for deployment via GitHub Actions), and a Supabase project

Phase 1 — Database Setup (First-Time Install)

This step is required before any users can save evaluations. Skipping it will result in "table not found" errors when saving cases.
1
Generate the Setup SQL
  1. Log in to ResolutionIQ as an admin user
  2. Navigate to Settings → Database Setup
  3. Click Copy SQL to copy the full setup script to clipboard

The SQL script creates the following tables if they don't exist: profiles, evaluations, evaluation_versions, and configures Row Level Security (RLS) policies.

2
Run the SQL in Supabase
  1. Open your Supabase project dashboard at supabase.com/dashboard
  2. Navigate to SQL Editor (left sidebar)
  3. Click New Query
  4. Paste the copied SQL
  5. Click Run
  6. Verify: look for success messages with no errors. If you see "already exists" notices on some tables, that is expected for re-runs.
Tip: The setup SQL is idempotent — safe to run multiple times. Running it again on an existing install will add any new columns added in recent versions without dropping data.
3
Verify Table Creation

In Supabase Table Editor, confirm these tables exist:

TableKey Columns
profilesid, email, full_name, approved, role
evaluationsid, user_id, loan_data, results, checked_docs, assignee_email, sla_start_date, foreclosure_sale_date, created_at
evaluation_versionsid, evaluation_id, version_number, snapshot, created_at
If checked_docs or assignee_email columns are missing, re-run the DB Setup SQL. These columns are required for case management features.

Phase 2 — First Admin User

4
Set Your User as Admin in Supabase

The first user to register will be in "Pending" status. To bootstrap the admin account:

  1. In Supabase, open Table Editor → profiles
  2. Find your user row (by email)
  3. Set approved = true
  4. Set role = admin
  5. Save the row

You can now log in and use the in-app User Management panel for all subsequent users — no more direct Supabase edits required.

Phase 3 — User Management

Approving New Users

  1. Navigate to Settings → User Management
  2. Users who have registered but are pending appear in the Pending Approval list
  3. Click Approve to grant access; Deny to reject
  4. Approved users are notified by email and can log in immediately

User Roles

RolePermissions
adminFull access: all evaluations, user management, servicer overlay configuration, DB setup
supervisorCan view all cases in the team's pipeline; can reassign cases; cannot modify overlays or manage users
specialistCan create, edit, and evaluate their own cases; can view cases assigned to them by supervisors

Deactivating Users

To remove access for a departed employee: go to User Management, find the user, and click Deactivate. Their existing cases remain in the system but are reassigned to the admin pool. Deactivated users cannot log in.

Phase 4 — Servicer Overlays

Servicer overlays allow your organization to apply stricter standards on top of investor minimums. Navigate to Settings → Servicer Overlays.

Overlay SettingDescriptionExample
Minimum FICO ScoreOptions requiring FICO below this floor are marked ineligible580 — no option recommended below 580 FICO
Maximum DLQ MonthsOptions only valid below a certain delinquency threshold18 — do not offer options on loans >18 months DLQ
Excluded Hardship TypesRemove specific hardship categories from eligibilityExclude "investment loss" for certain program types
Excluded OptionsDisable specific loss mitigation options globallyDisable "Deed-in-Lieu" if your servicer does not process DIL
Custom SLA WindowsSet servicer-specific evaluation SLA deadlines by investor30 days for FHA, 45 days for FNMA
Overlay changes apply immediately to all future evaluations. They do not retroactively change existing saved evaluations. Document all overlay changes with a dated rationale for your compliance file.

Phase 5 — Ongoing Administration

Weekly Tasks

  • Update the PMMS Rate in the platform settings with the current week's Freddie Mac Primary Mortgage Market Survey average (published every Thursday)
  • Review pending user approvals
  • Check for any overdue SLA cases in the Dashboard

Guideline Updates

ResolutionIQ subscription includes rule updates within 30 days of material investor guideline changes. When an update is deployed:

  • A release notification appears in the platform on login
  • The Regulatory Index document is updated to reflect the new citations
  • Existing saved evaluations are NOT retroactively re-evaluated — they reflect the guidelines at the time of evaluation (by design, for audit trail integrity)
Notify your loss mitigation team when a major guideline update is deployed so they know to re-evaluate any pending cases using the updated engine.

Data Backup

Supabase automatically backs up your database daily (Point-in-Time Recovery available on Pro plan). Additionally, admins can export the full evaluations dataset from the Portfolio tab as a CSV for local backup. Schedule a monthly export as part of your data retention procedures.

Access Log Review

Supabase provides database-level audit logs accessible from the Supabase dashboard under Logs → Database Logs. Review these periodically for unusual access patterns or failed authentication attempts.
