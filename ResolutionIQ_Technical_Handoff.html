5. Core Architecture — Eligibility Engine

5.1 Five Engine Functions

evaluateFHA(loan: LoanData): EligibilityResult[]
evaluateFNMA(loan: LoanData): EligibilityResult[]
evaluateFHLMC(loan: LoanData): EligibilityResult[]
evaluateVA(loan: LoanData): EligibilityResult[]
evaluateUSDA(loan: LoanData): EligibilityResult[]

Each returns an array of results — one entry per loss mitigation option:

interface EligibilityResult {
  option: string;        // e.g. "FNMA Streamlined Payment Deferral"
  eligible: boolean;     // always derived from nodes.every(n => n.pass)
  nodes: AuditNode[];    // every criterion evaluated
  note?: string;         // special conditions or program notes
  overlayBlocked?: boolean;   // true if a servicer overlay blocked an otherwise eligible option
  overlayReasons?: string[];  // which overlay rule blocked it
}

5.2 The Node System

Every single eligibility criterion is a "node." The node() helper is defined inside each engine function:

const nodes: AuditNode[] = [];
const node = (question: string, answer: string, pass: boolean, hint?: string) => {
  nodes.push({ question, answer, pass, ...(hint ? { hint } : {}) });
};

// Usage:
node("DLQ 2–6 months at evaluation", dlq+"mo", dlq >= 2 && dlq <= 6);
node("Hardship resolved", l.fnmaHardshipResolved?"Yes":"No", l.fnmaHardshipResolved);

// Eligibility is ALWAYS derived from all nodes:
const eligible = nodes.every(n => n.pass);
results.push({ option: "FNMA Payment Deferral", eligible, nodes });
Never compute eligible as a manual boolean expression. It must always derive from nodes.every(n => n.pass). This guarantees the audit trail is always consistent with the eligibility outcome.

5.3 Servicer Overlay Post-Processing

After the engine runs, overlays are applied as a post-processing filter. If an option is eligible but blocked by an overlay, it is marked ineligible with overlayBlocked: true and overlayReasons. The UI shows a 🚫 badge in the Results and Audit tabs for overlay-blocked options.

5.4 Terms Engine

calcApprovalTerms(optionName: string, loan: LoanData) — ~2,000+ lines. Computes new payment, capitalized UPB, partial claim amounts, rate reduction steps, cap checks, and amortization inputs. Called separately from eligibility — it is NOT called by the engine functions.

5.5 Waterfall Order

const WATERFALL_ORDER: Record<string, string[]> = {
  FHA:   ["FHA Reinstatement", "Repayment Plan", "Formal Forbearance", ...],
  FNMA:  ["FNMA Reinstatement", "FNMA Repayment Plan", ...],

7. Authentication & RLS

Auth Flow

  1. User registers → Supabase creates auth user → profiles row created with approved=false
  2. Admin approves in Settings → User Management → approved=true
  3. User logs in → loadProfile() reads profiles → if approved=false, shows "Pending" screen
  4. Role from profile gates UI features and is enforced by RLS at DB level

RLS Summary

  • specialist — read/write own evaluations rows + rows assigned to their email
  • supervisor — read all evaluations; can update assignee_email and status
  • admin — full access to all tables
  • servicer_overlays — all authenticated users can read; all authenticated users can write (admin-only enforced in UI)
If RLS permission errors appear, re-run the DB Setup SQL from Settings → Database Setup. It recreates all policies idempotently.

9. Key Patterns & Conventions

9.1 The set() Helper

const set = useCallback((field: keyof LoanData, value: any) => {
  setLoan(prev => ({ ...prev, [field]: value }));
}, []);

Use this for all single-field loan updates. Do not use setLoan directly for single fields.

9.2 negEscrow Pattern (all Payment Deferral options)

const negEscrow = escrowAdv > 0
  ? escrowAdv
  : (currentEscrow < 0 ? Math.abs(currentEscrow) : 0);

Used in all 6 Payment Deferral options (FNMA, FHLMC, FHA, USDA, disaster variants). Never deviate from this pattern for PD escrow calculations.

9.3 Loan Age Computation

const originationDate = loan.noteDate || loan.noteFirstPaymentDate;
const loanAgeMonths = originationDate
  ? Math.floor((Date.now() - new Date(originationDate).getTime()) / (30.44 * 86400000))
  : 0;

9.4 FIELD_MAP (LOS Import)

Maps every known LOS field name variant to the internal LoanData field. When adding a new field to initLoan, add its variants to FIELD_MAP. The same map is used by both JSON import and CSV single-row import.

9.5 Overlay Persistence Pattern

const overlaysLoaded = React.useRef(false);

// Load from Supabase after auth, fall back to localStorage
useEffect(() => {
  if (!profile) return;
  supabase.from("servicer_overlays").select("config").eq("org_id","default").single()
    .then(({ data }) => {
      if (data?.config) setOverlays(data.config);
      else { /* try localStorage */ }
    });
  overlaysLoaded.current = true;
}, [profile]);

// Save on change — guarded by overlaysLoaded to prevent premount saves
useEffect(() => {
  if (!overlaysLoaded.current) return;
  localStorage.setItem("riq_overlays", JSON.stringify(overlays));
  if (profile) supabase.from("servicer_overlays").upsert({...}).then(() => {});
}, [overlays]);

When adding other config that needs similar Supabase persistence, follow this pattern: guard saves with a React.useRef flag to prevent writing empty state before the initial load completes.

9.6 SLA Computation

const slaRule = SLA_RULES[loan_type];
const deadline = new Date(sla_start_date).getTime()
  + slaRule.evaluationDeadlineDays * 86400000;
const daysLeft = Math.floor((deadline - Date.now()) / 86400000);
// daysLeft < 0 = overdue; 0–7 = due soon

9.7 AdminUsersPanel Component

A standalone AdminUsersPanel component is defined just before the main ResolutionIQApp function. It queries profiles directly, shows all active users, and handles role updates and deactivation. It receives profile, adminMsg, setAdminMsg, and supabase as props.

Critical rule: The test files each contain their own inline copies of the evaluation functions (not imported from App.tsx — App.tsx is TypeScript; tests are plain ESM). When you change an eligibility rule in App.tsx, you MUST sync the exact same change in the corresponding test file's eval function. Failure to do so causes false test passes that mask real regressions.
Test file eval functions to keep in sync with App.tsx: evaluateFHA, evaluateFNMA, evaluateFHLMC, evaluateVA, evaluateUSDA in all test files that declare them.

13. Security Notes

  • The Supabase anon key is a public publishable key — safe in client-side code. RLS enforces data access at DB level.
  • The Supabase service role key is never used in this application. Do not add it.
  • The Claude API key is entered at runtime and never stored (not localStorage, not Supabase, not state).
  • The FRED PMMS fetch is a plain GET to a public federal endpoint. No loan data is sent.
  • All evaluation logic runs 100% client-side. Loan data is only sent to Supabase when a case is explicitly saved.
  • Loan data is PII-sensitive. Verify RLS policies are active before any production deployment (re-run DB Setup SQL if unsure).
